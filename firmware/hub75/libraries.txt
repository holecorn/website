Arduino libraries for the HUB75 build. These versions are what the sketch was
written against *and* what it has now been compiled against.

  ESP32 HUB75 LED MATRIX PANEL DMA Display   3.0.12   mrcodetastic
  PubSubClient                               2.8      Nick O'Leary
  ArduinoJson                                7.4.3    Benoit Blanchon

  Adafruit GFX Library                       1.12.6   Adafruit   <- transitive
  Adafruit BusIO                             1.17.4   Adafruit   <- transitive

The bottom two are not used by any code here. The HUB75 library's own header
includes Adafruit_GFX.h, so the build fails at the first #include without it, and
GFX in turn pulls BusIO. Library Manager installs them for you; arduino-cli does
not, which is how they came to be missing from this list for so long. Don't drop
them for being unreferenced.

Board: "Adafruit MatrixPortal ESP32-S3" from the esp32 package by Espressif.
FQBN: esp32:esp32:adafruit_matrixportal_esp32s3
Core: esp32:esp32 3.3.11

Credentials come from secrets.h, which is gitignored — copy secrets.example.h to it
before the first build. A missing one is a named #error, not a pile of undefined
identifiers.

Compiled clean on 2026-08-03 — no warnings from any file here, including at
--warnings all. 996,427 bytes of flash (47% of 2,097,152) and 81,052 bytes of
global RAM (24% of 327,680), leaving 246,628 for locals.

USE_TLS 1 also builds, checked the same day: 1,084,459 bytes of flash (51%) and
81,588 of global RAM. The ~88 kB is the real cost of the flag; the +536 bytes of
static RAM is not, because mbedTLS takes its handshake buffers off the heap. Not
that the board should use it — it has no clock, so there is nothing to validate a
certificate's dates against without SNTP succeeding first. See the mosquitto
config in docs/OFFLINE-SCOREBOARD.md, which puts the board on plain 1883 for
exactly that reason, and note the app's wss:// is a browser constraint rather than
the same choice made differently.

Flashed and run on 2026-08-03 with no panel attached: WiFi, PubSubClient and the
retained-state recovery all worked first try. Upload is

  arduino-cli compile --upload -p <port> -b <fqbn> firmware/hub75

and note the port changes after upload — the ROM bootloader enumerates as
cu.usbmodem<MAC> and the running sketch as cu.usbmodem101.

First light on one panel the same day: the wordmark and the score layout both drew,
so the pinmap and the FM6126A init are confirmed. Still untested: the second panel
and the chain, the brightness buttons, and the power figures.
